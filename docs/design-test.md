# テスト方針（MVP）

> 自分専用MVPのため、テストは「壊れると毎日困る計算ロジック」に限定する。

## 方針

- 全機能にテストは書かない
- **`lib/calc.ts` のユニットテストのみ**を作成する
- テストランナーは **Vitest** を採用する
- テストファイルは同階層に `lib/calc.test.ts` として配置する

## テストを書く対象（必須）

`lib/calc.ts` の以下ロジックはテスト対象にする。

- BMR（基礎代謝）計算（ハリス・ベネディクト式）
- METs × 体重 × 時間の運動消費計算
- 歩数からの消費カロリー計算
- 収支判定（`食べ過ぎ` / `いい感じ！` / `まだ食べれる`）

## テストを書かない対象（MVPでは不要）

- UIコンポーネント
- Server Actions / CRUD
- Gemini API連携

## 理由

- 計算ロジックは純粋関数にしやすく、仕様が明確でテスト効率が高い
- UIやCRUDは手動確認で十分に検知しやすい
- 外部APIモックのコストに対して、MVP段階でのリターンが小さい
- 計算式の小さなミス（係数・符号・境界条件）が、日々の数値ズレとして蓄積しやすい

## 最低限のテストケース目安

- BMR: 男性/女性それぞれ1ケース + 小数の丸め方確認
- 運動消費: 30分・60分など時間違いの2ケース
- 歩数消費: 0歩と10,000歩の2ケース
- 収支判定: `-200` / `200` の境界を含む3ケース
