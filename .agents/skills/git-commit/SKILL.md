# Git Commit

ステージングされた変更を分析し、コミットメッセージを生成して実行する。

## ワークフロー

1. `git diff --staged` でステージングされた変更を確認
   - **変更なし** → ユーザーに確認して終了
   - **変更あり** → 次へ
2. 変更内容からコミットタイプと要約を決定
3. コミットメッセージを生成
4. **MUST: AskUserQuestion** でコミットメッセージの承認を得る
   - 生成したメッセージを表示し、「コミットする」「修正する」の選択肢を提示
   - 承認されるまで実行しない
5. `git commit -m "<message>"` を実行（`Co-Authored-By` は追加しない）

## メッセージ規約

- **形式**: `<type>: <日本語の要約>`（最大25文字、1行）
- **内容**: ファイル名や関数名ではなく、機能やサービス上の名前で表現

**タイプ**: `feat` / `fix` / `refactor` / `style` / `docs` / `test` / `chore` / `perf` / `ci` / `build`

## 入出力例

| diff の変更内容            | コミットメッセージ           |
| -------------------------- | ---------------------------- |
| ルーム一覧ページの新規作成 | `feat: ルーム一覧画面を追加` |
| ログイン時の認証エラー修正 | `fix: ログインエラーを修正`  |
| 認証サービスの構造整理     | `refactor: 認証処理を整理`   |
| README.md の更新           | `docs: READMEを更新`         |
| 不要なimportの削除         | `style: 不要なimportを削除`  |
